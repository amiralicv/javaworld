## ✅ Checklist

Only now does this door open properly, and it opens *easily* from here.

- [ ] ML fundamentals — train/validation/test, overfitting, feature engineering, evaluation metrics
- [ ] Feature stores — and why they are mostly a data engineering problem
- [ ] Model serving, batch vs real-time inference
- [ ] **MLOps** — versioning data and models, reproducibility, monitoring drift
- [ ] LLM application patterns — embeddings, vector search, RAG pipelines (**these are data pipelines**)

**The honest framing:** in a real ML team the majority of the work is data plumbing, and you would already own it. You do not become an ML engineer by learning models. You become one by being the data engineer who also understands models. That is exactly the person these teams cannot find.

**Reality check for Iran:** heavy model training needs GPU compute and cloud services that are hard to access — see [[06 - Java Data Engineering/06 - Iran Playbook|Iran Playbook]]. Data-side ML work (features, pipelines, serving infrastructure) is far more reachable from where you are.
