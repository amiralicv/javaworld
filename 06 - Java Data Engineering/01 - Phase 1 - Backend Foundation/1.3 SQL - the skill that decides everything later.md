## ✅ Checklist

**This is the single highest-value item in the entire roadmap.** Data engineering is 60% SQL. Give it more time than you think it deserves.

- [ ] `SELECT`, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY` — fluent, no thinking
- [ ] **All join types**, and what happens to row counts in each (this is where most people are secretly weak)
- [ ] **Subqueries vs CTEs** (`WITH`) — and why CTEs are how real analytical SQL is written
- [ ] **Window functions** — `ROW_NUMBER`, `RANK`, `LAG`, `LEAD`, `SUM() OVER (PARTITION BY ...)`.
      *If you learn only one advanced SQL topic, learn this one.*
- [ ] **Aggregation patterns** — running totals, deduplication, "latest row per group", gaps and islands
- [ ] **Indexes** — B-tree, when an index helps, when it hurts, composite index column order
- [ ] **`EXPLAIN ANALYZE`** — read a query plan, find the sequential scan, fix it
- [ ] **Normalization** (1NF→3NF) and when to deliberately break it
- [ ] **Transactions & isolation levels** — dirty read, non-repeatable read, phantom read

**Practice, not reading:** solve real problems daily. Any SQL exercise site works — the discipline is *daily*, small, and always writing the query yourself before looking.

**Read:** *SQL Performance Explained* (Winand) — short, changes how you see databases forever.

> **You are done when…** you can write a window-function query with a CTE from memory, and you can look at a slow query plan and say *"the problem is here"* before anyone tells you.
