## ✅ Checklist

**Your Java background is a real advantage here.** Kafka is a JVM system; most people in data come from Python and are afraid of it. You are not.

- [ ] Topics, partitions, offsets, replication factor
- [ ] Producers — acks, idempotent producer, batching, compression
- [ ] Consumers — consumer groups, rebalancing, offset commit strategies
- [ ] **Delivery guarantees** — at-most-once, at-least-once, exactly-once, and why exactly-once is harder than the marketing says
- [ ] Keys and partitioning — how you control ordering
- [ ] Retention, compaction, and log-compacted topics as a state store
- [ ] **Schema Registry** — Avro/Protobuf, schema evolution rules, compatibility modes
- [ ] Kafka Connect — source and sink connectors
- [ ] **Debezium** — CDC from Postgres/MySQL straight into Kafka
- [ ] Kafka Streams *or* Flink — stateful stream processing, windowing, watermarks, late events

**Read:** *Designing Data-Intensive Applications* (Kleppmann) — by now you should be deep in it. Chapters on replication, partitioning, transactions, consistency, and stream processing are the theory behind everything in this note.

> **You are done when…** you can explain what happens to in-flight messages when a consumer crashes mid-batch, and design so that the answer is "nothing bad."
