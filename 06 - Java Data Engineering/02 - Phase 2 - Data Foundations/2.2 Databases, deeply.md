## ✅ Checklist

You used a database in Phase 1. Now understand what is inside it.

- [ ] **Postgres as your main tool** — you will self-host it, tune it, break it, fix it
- [ ] Storage internals — pages, heap, B-tree index structure, TOAST
- [ ] Write-ahead log (WAL) — and how it enables replication and change data capture (**remember this for Phase 3 CDC**)
- [ ] MVCC — how Postgres handles concurrent reads/writes, `VACUUM`, table bloat
- [ ] Query planner — statistics, `ANALYZE`, why the planner sometimes chooses wrong
- [ ] Partitioning — range and list partitioning for large tables
- [ ] Replication — primary/replica, sync vs async, read replicas
- [ ] Backup and restore — `pg_dump`, PITR. Do a **real restore drill.** A backup you never restored is not a backup.
- [ ] **NoSQL, conceptually** — key-value (Redis), document (MongoDB), wide-column (Cassandra), search (Elasticsearch/OpenSearch). Know *when* each fits. You do not need mastery.

**Read:** *Database Internals* (Petrov) — hard, worth it. Postgres official docs are excellent; read them like a book.

> **You are done when…** you can explain to a backend team why their query got slow after the table grew, using the query plan as evidence.
