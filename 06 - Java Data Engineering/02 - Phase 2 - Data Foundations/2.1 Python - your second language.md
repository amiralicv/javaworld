## ✅ Checklist

You keep Java. Java runs the JVM data world (Spark, Kafka, Flink). Python runs the orchestration and transformation world. **Data engineers use both.** This is an advantage, not a conflict.

- [ ] Core language — comprehensions, generators, decorators, context managers, `*args/**kwargs`
- [ ] Type hints + `mypy` — write Python like an engineer, not like a notebook user
- [ ] Virtual environments and dependency management (`venv`, `pip`, `uv` or `poetry`)
- [ ] `pathlib`, `datetime` and timezones (timezones will hurt you — learn them once, properly)
- [ ] File formats — CSV, JSON, JSONL, and later Parquet
- [ ] **pandas** — enough to be dangerous: load, clean, join, group, reshape.
      *Then learn its limits: it dies on data bigger than RAM. That limit is why Spark exists.*
- [ ] **Polars** — the modern fast alternative; learn after pandas
- [ ] `requests` + working with APIs, pagination, rate limits, retries with backoff
- [ ] `pytest` — you already know testing from Phase 1, just port the habit
- [ ] Logging (`logging`, structured logs) — never `print()` in production

> **You are done when…** you can write a typed, tested Python module that pulls from an API, handles failures and retries, and writes clean Parquet — and you would not be embarrassed if it went in a code review.
