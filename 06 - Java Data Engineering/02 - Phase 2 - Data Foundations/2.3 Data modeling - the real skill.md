## ✅ Checklist

Tools change every 3 years. Modeling does not. This is where senior data engineers separate from juniors.

- [ ] **OLTP vs OLAP** — different shapes for different jobs, and why you do not run analytics on the production database
- [ ] **Dimensional modeling** — facts and dimensions, star schema, snowflake schema, grain (**"what does one row mean?"** is the most important question in this whole field)
- [ ] **Slowly changing dimensions** — Type 1, 2, 3, and when each is correct
- [ ] Surrogate keys vs natural keys
- [ ] **Normalization vs denormalization** — and the cost trade-off of each
- [ ] Wide tables / One Big Table, and when it beats a star schema
- [ ] Data Vault — know it exists, know it is heavy, know why banks like it (**relevant to the Iranian market**)
- [ ] **Medallion architecture** — bronze (raw) / silver (cleaned) / gold (business-ready)
- [ ] Idempotent design — running the same load twice must not double your data
- [ ] Late-arriving data, backfills, and reprocessing history

**Read:** *The Data Warehouse Toolkit* (Kimball) — old, still the reference. Skim, don't memorize.

> **You are done when…** given a messy business description, you can draw a star schema on paper, state the grain of the fact table, and defend why you chose SCD Type 2 for one dimension and Type 1 for another.
